# ADR-005：单词、词形、词义和短语模型

## 状态

已接受 MVP 数据模型

## 背景

用户可能记录单词、短语、大小写变体、同形异义词或带上下文的词形。仅使用 `normalized_term + language` 唯一合并会把不同词义错误合并，也会丢失用户首次看到的原始形式。

## 决策

1. `words` 是用户的学习项，不是词典词条。学习项主键为 UUID；`term` 保存用户首次输入或确认后的展示形式，`normalized_term` 仅用于检索。
2. `entry_kind` 只允许 `word` 或 `phrase`。短语不强行拆分为多个单词；用户可以另外记录其中的单词。
3. `sense_key` 可空且不参与全局唯一约束。同一拼写在不同词义下可以存在多个学习项；只有用户确认或词典提供明确区分时才建立词义关联。
4. `word_forms` 使用独立表保存原始词形、规范化词形和 `surface/lemma/inflection/alias` 类型。词形关联不覆盖原始 `term`，合并和拆分必须产生审计记录。
5. `definitions` 使用独立表保存一个学习项的多条释义、词性、例句和 provider；第三方原始 JSON 不直接落库。
6. ECDICT 词典导入结果进入独立的只读词典数据库；用户学习库只保存用户确认或主动导入的释义快照及来源信息。
7. 规范化采用 Unicode NFKC、首尾空白折叠和大小写折叠；不移除内部空格、不把标点短语强制变成单词、不因规范化而自动合并已有学习项。
8. 默认语言为 `en`，但所有查询和主键范围均显式带语言字段，为未来扩展预留空间。

## 验收样例

- `Learn` 与 `learn` 可检索到同一候选，但不会覆盖用户保存的展示形式。
- `lead`（动词）和 `lead`（金属）可以并存，且复习进度互不影响。
- `learned` 可以作为用户确认的词形关联到 `learn`，但原始收词记录仍保留 `learned`。
- `take care of` 作为一个短语学习项保存，不能被自动拆成三个独立学习项。
