# ADR-007：SQLite 日志模式、备份与恢复

## 状态

已接受 MVP 基线

## 决策

1. 学习数据库和词典数据库分离；学习库可写，词典库导入后只读使用。
2. 每次打开连接启用 `foreign_keys=ON`、`journal_mode=WAL`、`busy_timeout=5000`，并在应用退出和备份前正确释放连接。
3. 使用版本化 `schema_migrations` 表管理迁移。迁移必须在事务中执行，应用启动时先完成迁移再打开主界面；未知版本阻止写入并提示备份/升级。
4. 备份使用 SQLite Backup API 或 `VACUUM INTO` 生成一致性副本，不直接复制正在写入的 `.db` 文件。备份文件带创建时间、应用版本和 schema 版本元数据。
5. 恢复流程先把用户选择的备份恢复到临时文件，运行 `PRAGMA integrity_check`，再用原子替换更新主数据库；失败时保留原数据库。
6. WAL、SHM 和临时文件不进入用户导出包；导出 CSV/JSON 由应用按数据模型生成。
7. 数据库写入失败不得静默丢弃收词或复习事件。界面显示可操作错误，并将诊断信息写入日志但不写入原句以外的敏感路径信息。

## 验收

- 并发读写时不出现“database is locked”未处理异常；超过 busy timeout 后显示明确错误。
- 应用异常退出后，重新启动可恢复 WAL 中已提交的数据。
- 备份恢复后，学习项、复习事件和熟练度状态保持一致。
- 迁移重复执行不会重复建表或丢失数据。
