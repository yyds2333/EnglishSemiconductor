# WordPin 项目实施规划书

| 项目 | 内容 |
|---|---|
| 文档版本 | 1.0 |
| 文档状态 | 执行基线 |
| 项目阶段 | 立项与开发前准备 |
| 产品形态 | Windows 桌面单词收集与复习工具 |
| 支持平台 | Windows 11 x64 |
| 最低系统基线 | Windows 11 24H2，OS build 26100 |

## 1. 规划目的

本规划书用于指导 WordPin 从规格修订、技术验证、开发、测试到发布的全过程。后续由 Codex 承担的需求、设计、编码、测试和文档任务，应先读取本规划书，确认当前阶段和出口条件，再开始执行。

本规划书解决以下问题：

- 后续任务按照什么顺序实施。
- 哪些决策必须在编码前完成。
- 每个阶段应交付什么成果。
- 如何判断一个阶段真正完成。
- 规格、代码、测试和安装包如何保持一致。
- 遇到新需求或技术风险时如何调整计划。

## 2. 项目目标

交付一个稳定、低打扰、本地优先的 Windows 11 x64 桌面应用，使用户可以：

1. 在其他应用中学习时快速收录英文单词或短语。
2. 通过置顶悬浮窗查看释义、上下文和熟练度。
3. 使用动态复习队列完成间隔学习。
4. 查看自己的稳定掌握量、回忆表现和学习趋势。
5. 备份、恢复和导出全部个人学习数据。

首版不以功能数量为成功标准。以下三项优先级最高：

1. 收词操作足够快且不打断当前学习。
2. 学习进度计算可解释、可测试且不会误导用户。
3. 用户数据在异常退出、升级和恢复过程中保持安全。

## 3. 固定约束

以下约束由产品负责人确认，除非后续明确变更，不再反复讨论。

| 编号 | 约束 |
|---|---|
| C-001 | 只支持 Windows 11，不支持 Windows 10 |
| C-002 | 只发布 x64 安装包，不发布 x86 或 ARM64 |
| C-003 | 应用默认使用简体中文 |
| C-004 | MVP 为单用户、本地优先、无需登录 |
| C-005 | 默认不持续监听剪贴板，只响应用户主动操作 |
| C-006 | 用户数据默认只保存在本机 |
| C-007 | 网络查询失败不得阻止收录单词 |
| C-008 | 应用必须支持系统托盘、全局快捷键和置顶悬浮窗 |
| C-009 | 每日复习使用软目标，不设置强制硬上限 |
| C-010 | 不以未经客观测试的结果宣称用户“已被系统验证掌握” |

### 3.1 Windows 版本策略

- 项目最低运行基线为 Windows 11 24H2 x64，build 26100。
- 主开发与发布测试基线为 Windows 11 25H2 x64。
- 对 Windows 11 26H1 x64 执行兼容性测试，但不使用 26H1 专属 API。
- 正式发布时，只对仍处于微软支持周期内的 Windows 11 版本提供正式支持。
- 如果某个 Windows 11 版本在项目开发期间停止服务，发布说明应将其标记为不再支持，不为此降低应用安全基线。

微软当前说明 Windows 11 采用年度功能更新节奏；24H2、25H2 和 26H1 的服务周期不同。项目每次发布前应重新检查微软的 [Windows 11 版本信息](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information) 和 [.NET Windows 支持列表](https://learn.microsoft.com/en-gb/dotnet/core/install/windows)。

## 4. 文档优先级与真相来源

发生冲突时，按以下顺序执行：

1. 产品负责人最新明确决定。
2. 已接受的架构决策记录（ADR）。
3. 最新版产品与开发规格书。
4. 本项目实施规划书。
5. 测试计划、设计稿和其他辅助文档。

当前《WordPin Windows 单词学习工具——产品与开发规格书 v1.1》是需求基线；v1.0仅作为历史参考。v1.1已收敛Windows 11 x64、词义/词形模型、今日会话快照和确定性熟练度算法。

## 5. 项目管理方式

## 5.1 工作项状态

每个任务使用以下状态：

| 状态 | 含义 |
|---|---|
| BACKLOG | 已记录，尚未安排 |
| READY | 依赖已满足，可以开始 |
| IN_PROGRESS | 正在执行；同一执行者同时只保留一个主要任务 |
| REVIEW | 实现完成，等待自审或产品确认 |
| BLOCKED | 缺少必要决策、权限或外部条件 |
| DONE | 代码、测试、文档和验收全部完成 |

## 5.2 优先级

| 优先级 | 定义 |
|---|---|
| P0 | 不完成就不能发布，或可能造成数据损坏、隐私问题、核心流程不可用 |
| P1 | MVP 应完成，但短期缺失不会损坏数据 |
| P2 | MVP 后增强 |

## 5.3 后续每次任务的执行协议

Codex接手后续任务时执行以下流程：

1. 读取本规划书、最新规格书、相关 ADR 和任务状态。
2. 检查工作区现有修改，保护用户已有内容。
3. 将请求映射到工作项和当前里程碑。
4. 确认依赖是否完成；发现阻断决策时先完成安全的调研和技术验证。
5. 实现范围内的代码、测试和文档，不扩大到无关功能。
6. 执行与风险相称的验证；核心算法、数据库迁移和备份必须执行自动化测试。
7. 更新任务状态、变更日志和相关规格。
8. 汇报完成内容、验证结果、剩余风险和下一项 READY 任务。

## 10. S3：数据层与数据安全

### 10.1 目标

建立可迁移、可审计、可安全备份的本地数据层。

### 10.2 数据原则

- 复习事件和遇见记录是不可变事实；聚合状态可以重算。
- 数据库迁移只允许前向迁移，禁止发布时删除数据库重建。
- 所有时间点使用 UTC 存储；“今日”边界使用当前本地时区计算。
- 数据库写操作使用事务和合理的 busy timeout。
- 不直接复制正在使用的 SQLite 主文件作为备份。

### 10.3 工作项

| ID | 工作项 | 优先级 | 依赖 |
|---|---|---:|---|
| S3-01 | 实现数据库连接、迁移和完整性检查 | P0 | S1、ADR-005/007 |
| S3-02 | 实现单词、词义、词形、遇见、标签和标记模型 | P0 | S3-01 |
| S3-03 | 实现复习事件、会话和队列快照模型 | P0 | S3-01、ADR-006 |
| S3-04 | 实现聚合状态重算和算法版本字段 | P0 | S3-03 |
| S3-05 | 使用 SQLite Backup API 或 `VACUUM INTO` 创建一致备份 | P0 | S3-01 |
| S3-06 | 实现备份校验、保留策略和恢复前备份 | P0 | S3-05 |
| S3-07 | 实现 CSV/JSON 导出及隐私提示 | P1 | S3-02、S3-03 |
| S3-08 | 实现软删除、回收站和撤销删除 | P1 | S3-02 |

### 10.4 备份触发

- 应用每天运行期间至少创建一次自动备份，不依赖重启。
- 当距离最近备份已有 24 小时，应用空闲后触发备份。
- 累计发生 100 次数据写入且距离最近备份超过 1 小时时，可以额外触发备份。
- 退出应用不强制创建备份，避免关机阻塞。
- 恢复前验证备份完整性、数据库版本和可迁移性。

### 10.5 出口条件

- 异常终止后已提交数据不丢失。
- 迁移、备份、恢复和损坏备份拒绝测试通过。
- 数据状态可以仅根据事实事件和算法版本重算。
- 10,000个单词的数据量下核心查询满足性能目标。

## 11. S4：收词与词典闭环

### 11.1 目标

实现“主动复制/输入—本地保存—词典补全—再次遇见”的完整闭环。

### 11.2 收词模式

首版明确采用两种模式：

1. 快速收词：用户先复制文本，再按快捷键；应用读取一次剪贴板并非激活式显示结果。
2. 手动输入：用户呼出悬浮窗并激活输入框，输入或粘贴单词。

首版不向其他应用模拟发送 `Ctrl+C`，避免破坏当前应用状态。后续如果增加“一键复制选区”，必须作为可关闭的实验功能单独设计。

### 11.3 工作项

| ID | 工作项 | 优先级 | 依赖 |
|---|---|---:|---|
| S4-01 | 实现剪贴板一次性读取、锁定重试和输入限制 | P0 | S2、S3 |
| S4-02 | 实现大小写、Unicode标点、撇号和连字符清洗 | P0 | ADR-005 |
| S4-03 | 实现单词、短语、同形词和词形候选判断 | P0 | S3-02、S4-02 |
| S4-04 | 实现立即本地保存和5秒撤销 | P0 | S3、S4-01 |
| S4-05 | 实现词典提供器接口、缓存、超时和重试 | P0 | ADR-003 |
| S4-06 | 实现无网络占位和后台补充查询 | P0 | S4-05 |
| S4-07 | 实现遇见次数、上下文、来源和备注 | P0 | S3-02 |
| S4-08 | 实现发音播放、失败降级和缓存策略 | P1 | ADR-003、S4-05 |

### 11.4 安全要求

- 第三方词典返回内容作为不可信输入处理，不执行HTML或脚本。
- 打开来源地址时仅允许明确白名单协议。
- 日志不记录完整剪贴板、完整原句、API密钥和本地文件内容。
- 对外发送查询前，隐私说明必须准确描述发送字段和服务提供方。

### 11.5 出口条件

- 正常、重复、无网、无结果、剪贴板空和剪贴板锁定场景全部通过。
- 本地记录建立不等待网络请求。
- 大小写敏感词和同形词不会被不可逆错误合并。
- 用户误触收录可以撤销。

## 12. S5：学习算法与每日队列

### 12.1 目标

实现可解释、确定、可版本化的学习状态计算和每日复习队列。

### 12.2 算法不变量

无论最终参数如何，必须满足：

- 相同历史下，EASY 的下次间隔不短于 GOOD。
- 相同历史下，EASY 达到相同等级的时间不得晚于 GOOD。
- AGAIN 必须降低稳定性并清除连续成功记录。
- 提前复习不得获得与足额间隔复习相同的稳定性奖励。
- L4/L5 必须经过跨日或长间隔回忆，不能在一天内刷出。
- 长期未复习只标记为待抽查，不在没有证据时自动判定遗忘。
- 所有计算对相同输入产生相同输出；MVP不使用随机扰动。
- 算法升级不得静默篡改历史事件。

## 18. 质量门禁

任何工作项只有同时满足以下条件才能标记DONE：

- 需求或技术决策有明确来源。
- 实现符合当前规格，没有未声明的范围扩张。

- 相关测试在本地通过。
- 用户可见行为有必要的错误状态和空状态。
- 数据结构变化包含迁移和回滚风险说明。
- 日志没有泄露敏感内容。

### 18.1 覆盖率底线

- 熟练度算法与队列：语句覆盖率至少90%。
- 数据库迁移、备份和恢复：核心路径至少90%。
- 其他领域与应用层核心模块：至少80%。
- UI以关键闭环自动化为主，不追求对所有视觉状态做机械覆盖。

覆盖率不是唯一质量指标。边界用例、故障注入和真实Windows集成测试优先于单纯提高数字。

## 20. 变更控制

## 24. 常见阻断与处理

### 词典服务无法合法缓存中文释义

停止实现具体提供器，保留接口和本地占位能力。重新比较可商用API、用户自带密钥和离线授权数据，不抓取无授权网页内容。

### 安装包在Windows 11显示未知发布者

内部测试可以继续，但不得作为公开正式版发布。准备代码签名证书，签名后重新执行安装、升级和校验值测试。

### 熟练度测试出现EASY比GOOD更晚升级

禁止通过只改一个阈值临时修补。运行完整序列模拟，重新平衡稳定性、复习次数和等级条件，并保留旧算法版本测试。

### 备份文件完整性检查失败

不得替换当前数据库。保留失败备份用于脱敏诊断，使用最近一个通过完整性检查的备份，并检查Backup API调用和磁盘状态。

### 窗口重启后出现在屏幕外

放弃保存坐标的直接恢复值，按当前显示器工作区、DPI和窗口最小可见区域重新钳制位置。
