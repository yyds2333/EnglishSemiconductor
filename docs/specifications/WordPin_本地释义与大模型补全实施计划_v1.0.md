# WordPin 本地释义与大模型补全实施计划 v1.0

## 1. 文档目的

本计划用于指导 WordPin v0.2.0 的设计、开发、测试和发布。目标是在 Windows 11 x64 客户端中完成以下能力：

1. 在应用内导入本地 ECDICT CSV，并安全生成或更新本地词典库。
2. 为学习中的单词手动添加、编辑、删除或恢复释义。
3. 本地没有对应释义时，按用户配置调用兼容的大模型 API 生成释义候选。
4. 清楚区分本地词典、用户编辑和大模型生成内容，让用户能够判断释义来源并确认结果。

目标读者是后续负责 WordPin 开发、测试、发布和维护的开发者。

## 2. 当前基线

- 当前正式版本：`v0.1.0`。
- 目标平台：Windows 11 x64，不增加其他系统或架构。
- 客户端技术：WPF、.NET 10、SQLite、Inno Setup。
- 学习数据库：`%LOCALAPPDATA%\WordPin\wordpin.db`。
- 本地词典数据库：`%LOCALAPPDATA%\WordPin\dictionary\dictionary.db`。
- 当前已有 ECDICT 流式 CSV 解析器、SQLite 词典存储和命令行导入工具。
- 当前应用仅展示本地词典结果；安装包不内置第三方词典数据。
- 当前 `definitions` 表已经存在，但尚未接入释义编辑、来源管理和大模型候选流程。

## 3. 产品原则

### 3.1 释义来源优先级

系统按以下顺序解析释义：

1. 用户手动保存或编辑的释义。
2. 用户已经确认的大模型释义。
3. 本地 ECDICT 词典释义。
4. 大模型新生成的“未确认候选”。
5. 无释义占位状态。

用户编辑内容永远优先。删除用户覆盖内容后，系统恢复显示本地词典结果，而不是删除底层 ECDICT 词条。

### 3.2 大模型结果不视为权威词典结果

大模型返回的是生成内容，可能出现错误、过度解释、词性不匹配或不存在的用法。系统必须：

- 显示“AI 生成 · 未确认”标记。
- 禁止把未确认结果直接写成用户已掌握的正式释义。
- 提供“采用”“编辑后采用”“重新生成”“忽略”操作。
- 保存提供方、模型、提示词版本和生成时间，保证结果可追溯。
- 不使用模型自报的置信度代替用户确认。

### 3.3 本地优先和隐私最小化

- 有本地或用户释义时不调用网络 API。
- 默认只发送单词或短语，不发送窗口标题、来源应用、剪贴板全文或其他学习记录。
- 例句上下文必须由用户单独开启；开启前显示将发送的字段。
- API 功能默认关闭，只有配置密钥并明确启用后才运行。
- 断网或 API 故障不得阻塞收词、复习和本地释义编辑。

## 4. 功能范围

## 4.1 应用内导入 CSV

在“设置 → 词典管理”增加导入入口。

### 用户流程

1. 用户点击“导入本地词典”。
2. 系统显示文件选择器，只接受 `.csv`。
3. 系统检查编码、表头、文件大小和必需字段。
4. 系统展示来源版本、词条样例和预计导入数量。
5. 用户确认后开始导入，并可查看进度或取消。
6. 系统在临时数据库中完成全部导入和完整性检查。
7. 导入成功后备份旧词典，并原子替换 `dictionary.db`。
8. 应用重新加载词典，不要求用户重启。

### CSV 规则

- 文件编码：UTF-8，允许 UTF-8 BOM。
- 必需列：`word`。
- 可选列：`phonetic`、`definition`、`translation`、`pos`、`exchange`、`audio`。
- 遵循 RFC 4180 引号和逗号转义规则。
- 单词最长 200 字符；单个释义字段最长 4,000 字符。
- 重复词条按 `term + language + provider_id` 更新。
- 非法行记录行号和原因；严重格式错误终止导入。

### 安全和恢复

- 禁止直接覆盖正在使用的正式词典数据库。
- 临时文件路径固定在 `%LOCALAPPDATA%\WordPin\dictionary\staging\`。
- 成功替换前保留旧文件，备份路径为 `backups\dictionary-{timestamp}.db`。
- 导入取消、崩溃或磁盘空间不足时保留旧词典。
- 最多保留最近 3 个词典备份。
- 导入报告显示成功数量、跳过数量、更新数量、耗时和错误摘要。

## 4.2 手动添加和编辑释义

在单词释义区域增加“添加释义”或“编辑”按钮。

### 编辑字段

- 中文释义：必填，最长 4,000 字符。
- 英文释义：选填，最长 4,000 字符。
- 词性：选填，最长 100 字符。
- 音标：选填，最长 200 字符。
- 例句：选填，最长 2,000 字符。

### 用户操作

- 新增释义。
- 编辑已有用户释义。
- 编辑本地词典或 AI 候选后，另存为用户覆盖内容。
- 删除用户覆盖内容，并恢复底层词典释义。
- 在关闭窗口前提示尚未保存的修改。
- 保存后立即刷新当前单词，不重启应用。

### 显示规则

- `用户编辑`：最高优先级，使用独立标签。
- `AI 已确认`：显示模型来源和确认时间。
- `本地词典`：显示词典版本。
- `AI 生成 · 未确认`：使用醒目但不阻断学习的提示样式。
- 同一个单词存在多条释义时按 `sort_order` 排序，首版最多显示 10 条。

## 4.3 大模型 API 补全

首版实现“OpenAI 兼容接口”适配器，以便用户配置支持兼容请求格式的服务。业务层不依赖具体厂商 SDK。

### 配置项

- 启用或关闭 AI 补全。
- API Base URL。
- API Key。
- 模型名称。
- 请求超时，默认 15 秒，允许范围 5–60 秒。
- 每日最大请求数，默认 30，允许范围 1–500。
- 是否自动在本地缺词时调用，默认开启但需先完成首次授权。
- 是否发送用户选中的例句上下文，默认关闭。

API Key 不写入 SQLite、日志或明文配置文件。Windows 11 版本优先使用 Windows Credential Manager；如实现成本不可接受，可使用当前用户范围的 DPAPI，并在 ADR 中记录取舍。

### 触发条件

只有同时满足以下条件才发起请求：

1. 用户已启用 AI 补全。
2. 用户已配置可用的 API Key、Base URL 和模型。
3. 用户释义、已确认 AI 释义和本地词典都没有结果。
4. 当前单词未命中冷却期或已拒绝缓存。
5. 当日调用次数未达到上限。

### 请求内容

默认发送：

```json
{
  "term": "serendipity",
  "language": "en",
  "output_language": "zh-CN",
  "context": null
}
```

提示词要求模型只返回结构化 JSON：

```json
{
  "term": "serendipity",
  "phonetic": "/ˌserənˈdɪpəti/",
  "part_of_speech": "noun",
  "definition_zh": "意外发现美好事物的机缘或能力",
  "definition_en": "the occurrence of finding valuable things by chance",
  "example": "The discovery was a happy case of serendipity."
}
```

客户端必须校验 JSON 结构、长度、必填字段、语言和内容类型。客户端不得渲染模型返回的 HTML、Markdown 链接或脚本。

### 请求状态

- `未配置`：显示“配置 AI 补全”。
- `等待请求`：保持本地收词流程可用。
- `生成中`：显示取消按钮和非阻塞进度。
- `未确认`：显示候选及采用、编辑、重试、忽略操作。
- `已确认`：写入学习数据库并作为正式释义。
- `失败`：显示简化错误和重试入口，不丢失单词。

### 成本和重复调用控制

- 同一标准化单词只允许一个并发请求。
- 已确认结果永久复用，除非用户删除。
- 相同请求成功但未确认时缓存 24 小时。
- 用户选择“忽略”后 30 天内不自动请求。
- HTTP 429、5xx 和网络中断最多自动重试 1 次，并使用退避延迟。
- 401、403、400 不自动重试，直接提示检查配置。
- 日志只记录请求 ID、状态码、耗时、模型和错误类别，不记录 API Key、完整提示词或返回释义。

## 5. 架构改造

## 5.1 新增应用层边界

保留现有 `IDictionaryProvider`，新增：

```csharp
public interface IDefinitionRepository
{
    Task<IReadOnlyList<SavedDefinition>> GetForWordAsync(Guid wordId, CancellationToken cancellationToken);
    Task<SavedDefinition> SaveAsync(DefinitionDraft draft, CancellationToken cancellationToken);
    Task DeleteAsync(Guid definitionId, CancellationToken cancellationToken);
}

public interface IDefinitionResolver
{
    Task<DefinitionResolution> ResolveAsync(
        WordRecord word,
        DefinitionResolutionOptions options,
        CancellationToken cancellationToken);
}

public interface ILanguageModelDefinitionProvider
{
    Task<GeneratedDefinitionCandidate> GenerateAsync(
        DefinitionGenerationRequest request,
        CancellationToken cancellationToken);
}
```

`IDefinitionResolver` 负责来源优先级和远程回退。WPF 界面不得直接调用 HTTP API、读取密钥或操作 SQLite。

## 5.2 数据库迁移 v3

将学习数据库版本从 2 升级到 3。扩展 `definitions` 表：

```sql
ALTER TABLE definitions ADD COLUMN source_kind TEXT NOT NULL DEFAULT 'manual';
ALTER TABLE definitions ADD COLUMN source_detail TEXT NULL;
ALTER TABLE definitions ADD COLUMN model_name TEXT NULL;
ALTER TABLE definitions ADD COLUMN prompt_version TEXT NULL;
ALTER TABLE definitions ADD COLUMN status TEXT NOT NULL DEFAULT 'accepted';
ALTER TABLE definitions ADD COLUMN generated_at TEXT NULL;
ALTER TABLE definitions ADD COLUMN confirmed_at TEXT NULL;
ALTER TABLE definitions ADD COLUMN created_at TEXT NULL;
ALTER TABLE definitions ADD COLUMN updated_at TEXT NULL;
```

约束由迁移后重建表或仓储校验保证：

- `source_kind`：`manual`、`llm`。
- `status`：`proposed`、`accepted`、`rejected`。
- 手动释义保存为 `manual + accepted`。
- AI 候选先保存为 `llm + proposed`，用户采用后更新为 `accepted`。

新增 `definition_request_cache` 表，记录标准化词、请求指纹、状态、冷却时间和调用计数。该表不保存 API Key。

## 5.3 词典导入服务

新增 `IDictionaryImportService`，将现有命令行工具中的能力复用到应用内：

- 流式读取，不一次加载完整 CSV。
- 临时数据库导入。
- 进度上报和取消令牌。
- `PRAGMA integrity_check`。
- 备份和原子替换。
- 重新打开词典提供器。

命令行导入工具继续保留，并与 WPF 使用同一个应用层服务，避免形成两套导入逻辑。

## 5.4 HTTP 和配置实现

- 使用 `HttpClient` 和统一超时，不引入厂商专属 SDK。
- 将 Base URL 限制为 `https://`；开发模式可显式允许 `http://localhost`。
- 禁止自动跟随到不同主机的重定向，避免 API Key 泄露。
- 限制响应正文大小，建议不超过 64 KB。
- 对模型输出执行 JSON Schema 校验和字段长度限制。
- 将普通设置写入 `settings` 表；密钥写入 Windows Credential Manager 或 DPAPI 文件。

## 6. 界面调整

### 6.1 主窗口

- 释义区域显示来源标签。
- 没有释义时显示“本地未找到释义”。
- AI 已启用时自动进入“AI 释义生成中”。
- 添加“添加释义”“编辑”“恢复本地释义”入口。
- AI 候选增加“采用”“编辑后采用”“重新生成”“忽略”。
- 网络请求不得冻结置顶窗口、剪贴板读取或复习按钮。

### 6.2 设置窗口

新增两个分区：

1. 词典管理：导入 CSV、查看版本、词条数量、最近导入时间、恢复备份。
2. AI 补全：启用开关、服务地址、模型、密钥、测试连接、每日额度、上下文授权。

“测试连接”只发送固定测试词，不保存为学习记录。测试结果只显示成功、鉴权失败、超时、限流或响应格式不兼容。

## 9. 验收标准

v0.2.0 只有满足以下条件才允许发布：

1. 用户能在图形界面中导入合规 CSV，无需安装 .NET SDK 或使用命令行。
2. 用户能为当前学习单词添加和编辑释义，重启后数据不丢失。
3. 用户删除自定义释义后能恢复显示本地词典释义。
4. 本地缺词且 AI 已启用时，系统能异步生成释义候选。
5. AI 候选始终标记为未确认，只有用户采用后才成为正式释义。
6. 相同单词的重复操作不会产生重复并发调用。
7. API 密钥不出现在 SQLite、日志、崩溃报告、导出文件或 Git 仓库中。
8. 达到限额、断网、鉴权失败或模型输出异常时，收词和复习仍然可用。
9. 从 v0.1.0 升级到 v0.2.0 不丢失单词、遇见记录和熟练度。
10. 所有自动化测试通过，Windows 11 x64 安装升级验收通过。

## 10. 风险和应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 大模型产生错误释义 | 用户学到错误内容 | 未确认标签、人工采用、来源记录、可编辑和拒绝 |
| API 成本失控 | 用户产生意外费用 | 每日限额、去重、缓存、调用前明确启用 |
| API Key 泄露 | 账户和费用风险 | Credential Manager/DPAPI、日志脱敏、禁止跨主机重定向 |
| CSV 来源许可不清楚 | 发布和分发风险 | 应用不内置数据包，导入页要求用户确认来源并记录版本 |
| 大词典导入损坏现有库 | 本地释义不可用 | staging、完整性检查、原子替换和备份恢复 |
| AI 请求拖慢主窗口 | 影响置顶收词体验 | 全异步、可取消、独立超时、不阻塞本地保存 |
| 词义与上下文不匹配 | 候选释义偏离实际语境 | 可选发送用户选中例句，默认关闭；用户最终确认 |
| 兼容接口行为不一致 | 返回格式解析失败 | JSON Schema、测试连接、清晰错误、适配器隔离 |

## 11. 版本和交付物

- 目标版本：`v0.2.0`。
- 安装包：仅 Windows 11 x64、自包含、per-user 安装。
- 代码交付：Domain、Application、Infrastructure、WPF、迁移和测试。
- 文档交付：AI 补全 ADR、隐私说明、CSV 导入指南、API 配置指南、升级说明。
- 发布交付：安装包、SHA-256、Release Notes、已知问题清单。

## 12. 推荐实施顺序

按 `A → B → C → D → E` 执行。先完成手动释义和安全 CSV 导入，再接入 AI。这样即使 API 方案调整，用户仍然可以完整使用本地释义功能；同时 AI 结果可以复用已经验证的编辑、确认和来源追踪流程。

开发开始前只需要确定一个产品选择：v0.2.0 首个实际联调的大模型服务和默认模型名称。代码保持 OpenAI 兼容接口，避免将业务逻辑绑定到单一厂商。

## 13. 预估周期

以下估算按单一开发分支持续实施计算，不包含第三方 API 账户审批或词典许可证人工复核等待时间：

| 阶段 | 预估工作量 |
|---|---:|
| A：数据模型和仓储 | 1–2 个工作日 |
| B：手动释义编辑 | 1–2 个工作日 |
| C：应用内 CSV 导入 | 2–3 个工作日 |
| D：大模型 API 和候选确认 | 3–4 个工作日 |
| E：升级验证、文档和发布 | 2 个工作日 |
| 合计 | 9–13 个工作日 |

每完成一个阶段都保持主分支可构建、测试可运行。B 和 C 完成后可生成内部测试包；D 完成后生成 v0.2.0 候选包；E 完成后发布正式版。

## 14. 本版本不包含

- 不在安装包中直接分发 ECDICT 或其他第三方完整词典数据包。
- 不进行自动网页抓取、搜索引擎爬取或绕过网站访问限制。
- 普通大模型接口只生成释义候选，不宣称已经实时检索或查证互联网来源。
- 如果未来接入带 Web Search 工具的模型，必须新增检索提供器、来源 URL、引用时间和许可审查，不能复用“无来源的 AI 候选”标记。
- 不实现多个模型服务之间的自动故障转移。
- 不同步 API Key 到云端，不在设备之间同步密钥。
- 不在本阶段实现发音音频生成、OCR 收词或浏览器扩展。
